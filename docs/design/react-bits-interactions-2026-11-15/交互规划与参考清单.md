# 大环线项目：React Bits 交互参考与实施建议

日期：2026-11-15。状态：评审方案，未改动业务页面。

## 目标与判断依据

把线网探索中的选择、等待、结果揭晓和返回衔接起来，让地图与分析的表现更有设计感。保留地图主画布、17 城切换、线路官方颜色、底部功能入口、手机端操作以及既有分析计算口径。

本方案依据当前项目代码结构与 React Bits 官方组件说明制定，是交互规划，不是已完成的视觉验收或性能测试。相对成本表示结合现有页面改造的预计难度，尚不是工期承诺。

当前项目为原生 HTML/CSS/JavaScript 与 SVG，React Bits 为 React 组件参考。默认提取交互思路，在现有技术中实现；直接使用源代码之前需要另行核对该组件依赖、许可和兼容性。无须为本轮视觉迭代迁移整个项目。

原页面的地图和线路色是主体。用户希望引入 React Bits 的光照、卡片和动态表现，因此在分析入口和浮动控件局部保留这些审美；表格、站名和图表数值以可读性为优先。几种导航方案互为替代，数字方案互为替代，不叠加安装。

## 优先试做的具体交互

### H1：分析入口采用 Magic Bento 的组合卡片

参考：[Magic Bento](https://www.reactbits.dev/components/magic-bento)。官方示例包含组合卡片、图形、边缘光与点击波纹。本项目借鉴卡片层级和局部反馈，内容采用线网自身的形状。

- 六个入口完整保留：直达矩阵、中心性排行、城市线网之最、方向玫瑰图、绕路之王、故障影响模拟。
- 桌面为紧凑的两列组合卡片；线网之最或绕路之王作为一个较明显的入口，其余入口保持同样易发现。
- 卡片内放一幅简洁的线网主题小图：环线、直线与绕行对比、断开的区间、玫瑰扇区。小图用于识别功能，不伪装成计算结果或实时数据。
- 鼠标进入时边缘与局部图形响应；键盘聚焦显示同样明确的边框或底色；触屏按下有反馈。
- 手机改为紧凑的双列或单列，按实际宽度决定；名称与功能短说明直接可读，不能依赖悬停显现。

验收：六个入口无需翻到长页面底部才能找到；点击区域至少 44px；光效不改变线路语义色；键盘和触屏都可直接进入模块。

### H2：排行借鉴 Animated List 的选择反馈

参考：[Animated List](https://www.reactbits.dev/components/animated-list)。官方组件是带入场与选择反馈的滚动列表，不能将它等同于现有复杂表格的直接替代品，也不代表它已经解决表格排序动画。

- 绕路之王和故障 Top 10 初次展示时，可见的前几行轻微依次出现，总额外等待控制在约 300ms 内；按钮立即可用。
- 当前行的背景、细标记和站名有统一的选中反馈；查看地图再返回，原行和滚动位置保留。
- 中心性数百行不做逐行入场。排序和筛选立即得到最终数值，优先保持姓名、数值和行对应关系稳定。
- 若后续加入行重排动画，需要稳定的站点/站对标识；只移动行内容，不对 sticky 表头或固定列叠加变换。
- 手机保留适合阅读的行/卡片布局；桌面完整表格继续支持排序，不因动效丢失指标。

验收：快速多次排序、横向与纵向滚动后不重叠；固定列与表头无错位；排序后选中项对应正确；长列表滚动时不反复播放动画。

### H3：关键数字采用 Count Up 的结果变化

参考：[Count Up](https://www.reactbits.dev/text-animations/count-up)。与滚轮式 Counter 二选一，第一版采用较易阅读的 Count Up 思路。

- 适用：线网之最的途经车站/区间/估算距离，故障模拟的新增不可达、绕行、未变化数量。
- 不适用：表格中的全部数字、车站名称、每帧计算进度、排序过程。
- 新结果返回后，摘要数值在约 400–600ms 内收敛到最终值；结果数据本身立即可复制、可读。
- 零值直接显示 0；千分位、小数位和单位保持原口径。只在结果发生变化时播放，返回页面不重播。
- 不以动画伪造后台计算进度，不把估算距离包装成精确运营里程。

验收：屏幕阅读器只播报最终结果；复制得到最终值；切换城市不会出现前一城市的晚到数字；减少动态效果时直接显示最终值。

### H4：抽屉与弹层采用 Staggered Menu 的开合节奏

参考：[Staggered Menu](https://www.reactbits.dev/components/staggered-menu)。借鉴开合与内容错峰的节奏，不照搬全屏网站导航。

- 点击底部分析入口，抽屉从现有位置展开；遮罩、面板、首组内容相互衔接。
- 开启约 200–280ms，关闭略快；只让少数组内容错开，不让每个字段依次等待。
- 手机面板遵循上下展开方向，桌面遵循现有抽屉位置；关闭动作与返回地图的动效方向一致。
- 切换分析模块时保留明确的来源和返回路径；动画中点关闭、连点开关都能中断并收敛到正确状态。

验收：Esc、关闭按钮、焦点回归和遮罩行为正确；移动端地图手势不会被隐藏面板截获；计算结束后的晚到结果不重新打开已关闭弹层。

## 第二批的具体建议

### M1：Pill Nav

参考：[Pill Nav](https://www.reactbits.dev/components/pill-nav)。提取选中底色、指示点移动的思路。城市标签完整保留中文名称，选中后自动滚动到可见区域。底部五个主要入口维持固定位置；城市切换加载时区分“已选择”与“数据加载中”。约 180–240ms 完成反馈。

原因：用户能看清自己从哪里切换到哪里，成本较小且桌面、触屏都成立。Gooey Nav 是更夸张的替代版本，第一版不与 Pill Nav 同时采用。

### M2：Spotlight Card

参考：[Spotlight Card](https://www.reactbits.dev/components/spotlight-card)。只放在 H1 分析卡片的边缘或空白区域；一张卡片最多一种光照，Magic Bento 已提供相同效果时不再叠加。浅色主题以边缘和底色变化为主，深色主题可有局部微光。

原因：能增加材质感，但几乎没有独立的移动端收益，因此作为 H1 的桌面增强而非独立大工程。

### M3：Gradual Blur

参考：[Gradual Blur](https://www.reactbits.dev/animations/gradual-blur)。只在确实仍有内容的滚动边缘出现窄幅渐隐/模糊；滚动到底后对应边缘消失。城市名称、数字和可点击控件必须有可读区域；表头和固定列不加此效果。

原因：让边缘更有层次，并暗示可继续滑动。若手机性能或可读性受影响，退回简单的边缘遮罩，不以持续模糊整片地图换取材质感。

## 需要先做小样的候选

| 候选 | 可接受的用法 | 暂不全量使用的原因 |
| --- | --- | --- |
| [Split Flap Text](https://www.reactbits.dev/text-animations/split-flap-text) | 一处结果标题或数字，短暂翻页后稳定；中文整词翻页优先 | 英文字母翻牌不能直接推广为中文站名支持；频繁翻牌影响辨认，不模拟不存在的实时列车信息 |
| [Click Spark](https://www.reactbits.dev/animations/click-spark) | 借鉴动作回应，改为已选站点的一次圆环扩散 | 原组件火花不等于地铁站波纹；只能在选站成功后反馈，不能让拖图、缩放也冒火花 |
| [Dock](https://www.reactbits.dev/components/dock) | 桌面底部图标轻微放大，点击中心和栏高度保持稳定 | 手机没有悬停；放大会遮挡地图；与 Pill Nav 是导航层的选择，需比较后决定 |
| [Glass Surface](https://www.reactbits.dev/components/glass-surface) | 个别浮动小控件的材质实验 | 折射可能扭曲站名与线条；浏览器支持和设备开销需实际测量，统计面板不应用强折射 |
| [Stepper](https://www.reactbits.dev/components/stepper) | 故障模拟顶部的非强制阶段提示 | 原有单页操作更直接；不能为展示步骤而增加多个下一步按钮，也不能声称该组件就是现有路书时间轴 |

## 大环线自身的特色动效：应单独规划

优先级高，相对成本中至高。这些是基于项目 SVG 与真实分析数据的定制开发，不是 React Bits 现成组件。

### 绕路之王

选中站对后，先标出两个端点与直线，再绘出对应的地铁路线；直线和路线使用明确不同的线型。地图按完整路线平滑聚焦，并避让路书。约 0.6–1 秒表现主要对比，可立即跳到最终结果；长路线压缩绘制时长，不让用户等完每一站才能操作。

原因：直接表现“近在眼前却要绕很远”，最能形成项目辨识度。原有最短距离与最少区间两种路线仍分别展示，不能把两者的指标拼在同一条路径上。

### 故障影响模拟

确认模拟后，先把实际停用对象标为中断，再显示真实计算出的不可达与绕行统计。路线示例可以绘出模拟前后对比。单站或区间的受影响展示只能使用计算确实提供的数据，不把站对计数任意推导成整片地理影响区，也不将粒子扩散当作乘客流量。

### 方向玫瑰图

城市/线路切换后，按官方线路色短暂展开扇区，再稳定为最终图形。若增加地图与扇区联动，需要新建独立的选择状态和高亮逻辑，不是加一个动效即可完成。统计仍按既定长度权重和估算区间口径计算，动画只影响呈现。

## 本轮暂不纳入

- 全屏粒子、流体、极光等持续背景：地图本身已是高密度图形，持续背景会与线路竞争，并占用手机性能。
- Splash Cursor、Blob Cursor、Target Cursor 等指针替换/拖尾：与精确选站、拖图有冲突，触屏收益也有限。
- Tilted Card、强 3D 翻转：不用于路线数值、排行表格、线路图，以免变形与点击区域不稳定。
- Scroll Stack、自动 Card Swap：排序结果和路线详情需要稳定顺序、可反复比较；叠卡会隐藏结果，自动轮播会打断读取。
- Glitch、Decrypted、Typewriter：不用于站名、城市名和计算进度；中文辨认和及时读取比乱序揭晓更重要。
- 全站磁吸按钮：选站、排序、关闭等操作的命中区域必须稳定。

## 统一动效参数与实施要求

以下为本项目建议参数，非 React Bits 默认值或实测结论。

- 按压反馈约 100–140ms；导航选中约 180–240ms；面板开合约 200–280ms；结果摘要约 400–600ms；地图完整路线揭晓控制在约 1 秒。
- 同一动作同时突出的元素最多 2–3 组，其他内容保持可读。动画不推迟实际计算或数据可用时间。
- 手机不能依赖 hover。按压与焦点反馈具有同样清晰的选中语义，最小点击区域约 44px。
- 减少动态效果时，跳过移动、缩放和计数过程，直接呈现完整结果。后台页签、已关闭弹层和不可见列表停止动画。
- 尽量变换 transform 与 opacity；表格的 sticky 单元格、排序后的行、弹层层级要特别验证。绘制 SVG 路径需要另测设备性能。
- 浅色、深色各自调整光效强度，官方线路色维持数据语义。零、缺失、加载、失败不能被动画掩盖。

## 实施批次

1. 第一批：H1 分析入口与 H4 开合统一；H2 在绕路 Top 10 试点；H3 在故障结果摘要试点。验证一套完整“进入—选择—结果—地图—返回”流程。
2. 第二批：加入 M1/M3；H1 合入可选 Spotlight；把已验证的列表与摘要节奏推广到中心性及线网之最。地图路线绘制单独做原型，与第一批界面一起评审。
3. 第三批：从翻牌、Dock、玻璃材质中选一项做对照样例；不默认全部上线。

优先级是开发顺序建议，不是当前已获逐项实施授权。后续按用户选定范围创建独立本地开发分支，验收后再发布。

## 评审与验收清单

- 桌面 1440、平板 768、手机 390 三档，并覆盖横屏；浅/深主题；减少动态效果设置。
- 真机检查触控拖图、双指缩放、软键盘、安全区和持续滚动，截图不能代替这些交互验收。
- 排行表格横向滚动、纵向滚动、连续排序、切换城市和返回原行均不重叠、不丢选中项。
- 不因装饰隐藏指标、站名、来源入口、估算说明；六个分析模块仍可完整进入。
- 动画期间按钮可用；快速关闭与重开、任务取消、异步晚到结果不会造成状态串用。
- 抽屉和弹层保留焦点约束、Esc 和焦点回归；图表键盘选择与触屏选择都有可用路径。
- 自动化验证数值、路线、选择状态；浏览器与真机验收动效和布局。现有 78 项测试不能直接证明新动效的质量或兼容性。
