高优先级 · H1

手机与平板的分析表格需要专门布局

发现与证据：已实测：390×844 下绕路表格容器宽 320px、内容宽 898px；768×1024 下为 679px / 898px。站名列 position 为 static，横向滚动后会失去站对身份。中心性表格在手机上将线路徽标和“全部站覆盖数”挤成多行竖排。

读者无法在同一视野比较“哪两个站、要绕多少区间、涉及多少条线”，旧中心性表格也明显降低了扫描效率。

建议调整与验收标准

建议：桌面保留全部指标和可排序表头。手机先展示站对、当前排序指标和“查看路线”，展开行显示其余指标；所有指标仍可通过紧凑排序控件访问。若保留完整横向表格，则固定站对列、提供明确的横向滚动提示。中心性手机行改为“站名＋主指标”，线路徽标横向换行，次级指标放详情。

验收：390、768、1440 三档均能识别站名和当前排序指标；不出现逐字竖排；横向滚动时站对仍可识别；现有每个数值指标的升降序能力保留。

补全分析弹窗的关闭、焦点和命名

发现与证据：已实测：绕路弹窗按 Escape 后仍为 display:flex；故障弹窗关闭按钮上按 Shift+Tab，焦点移到背景的 btn-open-failure。弹窗虽有 role=dialog、aria-modal=true，却没有 aria-labelledby 或 aria-label。

键盘使用者可能在看不见的背景上操作；Esc 与其他分析浮层的行为不一致，辅助技术也得不到明确弹窗名称。

建议调整与验收标准

建议：把研究弹窗接入现有统一退出逻辑；打开时记录触发入口，Tab 在弹窗内循环，关闭后归还焦点。用 research-title 作为可访问名称。优先复用现有弹层机制；必要时采用原生 dialog，保持当前外观。

验收：Esc 关闭最上层弹窗；Tab/Shift+Tab 均不进入背景；关闭后焦点回到原入口；辅助技术可读出“绕路之王”或“故障影响模拟”。

中优先级 · M4

把排序依据和不同路线的指标归属说清楚

发现与证据：已核对：默认按最少区间降序，最醒目的数值却是红色绕行系数；每个未激活表头都显示红色双向箭头。最少区间与最短估算距离独立计算，而线路数仅属于最短距离代表路线。

读者可能以为排行按红色倍数排序，或把线路数、距离和区间数误认为同一条路线的所有属性。

建议调整与验收标准

建议：结果标题旁明确“按最少区间 ↓”，仅激活排序列展示强调箭头。将线路数标为“线路数·距离路线”，提供就近口径提示；查看路线的两个动作继续保留，并在详情中清楚标注当前使用哪种路线。站对是无序组合，表格可用“站A ↔ 站B”，实际路书仍保留方向。

验收：任何一次排序后，当前指标和方向清晰可见；全部指标仍可排序；线路数说明始终与其对应路线一致；不擅自更换已确认的排行算法。

完善后台计算、取消和失败恢复的反馈

发现与证据：已核对：后台排行已有“完成x/总数”和取消动作，排行完成后有本次页面会话缓存；单次模拟错误提示要求重新打开重试。顶部普通结果、计算状态和错误状态共用相近的长段落样式。
