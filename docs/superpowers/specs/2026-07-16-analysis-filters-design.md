# 分析模块筛选优化设计

## 目标

优化“直达矩阵”和“中心性排行”的分析入口，降低用户在多城市、多车站数据中的查找成本，并保证桌面端和移动端都能完成筛选、查看结果和回到地图的完整操作。

## 范围

### 直达矩阵

保留两个筛选器：

- 城市
- 起始车站

不增加终点车站筛选器。起始车站为空时展示当前城市全部直达关系；选择起始车站后，展示该站到所有可达车站的直达结果。

起始车站选项按“线路 -> 车站”分组展示。线路分组使用对应线路官方颜色的彩色标识。换乘站可以出现在其所属的多个线路分组中，但底层筛选值必须指向同一个车站实体，避免重复计算。

切换城市后，使用新城市数据重建车站选项，并清空原城市的起始车站选择。点击结果时沿用现有地图定位和路书打开流程。

### 中心性排行

在现有中心性参数区域增加城市选择器。城市切换只更新排行数据和筛选选项，不立即改变地图城市；用户点击具体车站时，再将地图切换到对应城市并定位车站。

现有 Space L / Space P、站数限制、覆盖车站数限制、排序和线路彩色标识继续保留。中心性计算继续使用已有缓存机制，缓存键必须包含城市和分析参数，避免跨城市复用错误结果。

## 交互与布局

桌面端保持紧凑的横向筛选布局。移动端将筛选区域改为可换行或分层布局，保证标题、关闭按钮和筛选控件不互相遮挡。分析结果区域独立滚动，筛选区域不被结果表格或底部安全区遮挡。

线路分组选项需要具备足够的触控高度；打开分组列表后可滚动浏览，选择车站后刷新结果并收起列表。矩阵表格在小屏幕上允许横向滚动，关闭按钮始终可点击。

## 状态与数据流

1. 打开分析模块时，以当前城市作为默认分析城市。
2. 城市选择变化后，重置依赖该城市的车站选择，并刷新分析数据。
3. 起始车站筛选变化后，重新渲染矩阵，不修改全局地图路线状态。
4. 用户点击矩阵结果或中心性车站时，将结果转换为现有地图和路书流程需要的站点对象。
5. 地图切换和分析弹层关闭沿用现有应用状态管理，避免新增并行的路线状态。

## 实现边界

预计只修改 `index.html` 和 `styles.css`。不新增依赖，不修改地铁原始数据、路线求解器或城市极值预计算结果。

## 验收标准

- 可按城市筛选直达矩阵。
- 可按线路分组选择起始车站，并显示彩色线路标识。
- 选择起始车站后展示该站到所有可达车站的结果。
- 可按城市切换中心性排行，现有中心性参数和排序正常工作。
- 桌面端筛选器、表格、关闭按钮和结果点击均可操作。
- 移动端筛选器可见、可滚动、可点击；表格可横向查看；关闭和查看地图/路书操作不被遮挡。
- 现有回归测试、脚本语法检查和差异检查通过。
