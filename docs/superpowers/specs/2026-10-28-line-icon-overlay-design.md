# 地图放大线路牌设计

## 目标

在线网地图放大到足以阅读细节时，在高密度区域补充彩色线路牌，帮助用户辨认线路归属。线路牌采用已确认的 A 方案：带官方线路颜色的胶囊形标签，显示完整线路名称。

## 用户可见规则

- 地图缩放比例小于 `2.0` 时不显示线路牌，避免全网视图产生噪声。
- 达到 `2.0` 后，仅为当前视口内且有安全位置的线路显示线路牌。
- 每条线路在当前视口最多显示一个线路牌；同一线路不重复堆叠。
- 线路牌在默认灰色线网模式和官方线路颜色模式下都显示，线路牌始终使用官方线路颜色。
- 线路、站点、站名和路线高亮的视觉优先级高于线路牌。
- 如果线路牌没有不遮挡的位置，则本次不显示，不强行覆盖线路、车站或站名。
- 线路牌随缩放、拖动、切换城市、路线高亮和站名布局刷新而重新计算，位置不固定。

## 图层与数据边界

新增独立的 `line-badges-group`，位于基础线路之后、站点和站名之前或由明确的 z-order 控制；不改变基础线路、站点数据、路线求解和站名文本。

线路牌数据只使用当前城市已经存在的边数据：线路名称、线路颜色、两个端点坐标。无需新增经纬度字段或修改拓扑数据。

## 候选位置与避让

每条线路从当前可见边中生成有限候选点，优先级依次考虑：

1. 线段长度较长且方向稳定；
2. 候选点周围距离车站和换乘节点更远；
3. 候选标签与视口边界有足够余量；
4. 与其他线路牌的间距更大。

候选标签矩形必须避让：车站命中区域、已放置站名矩形、路线高亮元素和已放置线路牌。候选点全部冲突时跳过该线路。

## 响应式限制

桌面端允许显示当前视口内的全部可放置线路牌；移动端降低标签字号、内边距和候选数量，并设置总量上限，避免小屏密集显示。线路名称过长时允许胶囊牌自然变宽，但不能超出视口；若所有候选位置都会造成溢出，则隐藏该牌。

## 性能边界

线路牌计算只在以下事件后触发：缩放结束、拖动结束、城市切换、路线高亮变化和官方颜色开关变化。拖动或缩放进行中只更新已有 SVG transform，不在每个指针事件中重新布局。候选点和线路颜色可按城市缓存，避免重复计算。

## 可访问性与降级

线路牌属于辅助视觉信息，不承担唯一交互入口；每个线路牌提供 `aria-label`，站点仍保持原有键盘和触摸操作。浏览器不支持 `getBBox()` 或布局计算异常时，保留线路和站名，不渲染线路牌。

## 验收标准

- `scale < 2.0` 时线路牌全部隐藏，`scale >= 2.0` 时可按避让结果出现。
- 同一视口内同一线路最多一个线路牌。
- 线路牌不与车站标记、站名、其他线路牌和路线高亮矩形相交。
- 默认灰色线网和官方颜色线网都能正确显示彩色线路牌。
- 拖动、缩放、切换城市和路线规划后没有残留旧线路牌。
- 移动端不出现横向溢出、标签裁切或明显遮挡。
- 不改变既有站点选择、站名碰撞布局、路线计算和地图颜色开关行为。
