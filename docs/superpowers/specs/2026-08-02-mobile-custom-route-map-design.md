# 移动端自定义路线地图优化设计

## 目标

提升移动端自定义路线规划时的地图可操作面积、车站选择准确性，以及全图缩小状态下的拖动和缩放流畅度。既有的选站顺序、允许重复车站、自动补全最少经过站点路径和确认后进入路书的业务逻辑保持不变。

## 交互设计

### 地图优先面板

- 进入自定义模式后，底部面板默认收为约 96px 的摘要条。
- 摘要条显示已选车站数、撤销和确认操作；确认按钮始终可见且可点击。
- 点击摘要条或向上滑动可展开完整的路线统计与操作区；向下滑动恢复摘要状态。
- 展开状态沿用现有移动端面板高度，桌面端不改变。

### 车站选择

- 移动端为每个 SVG 车站增加不影响视觉的透明点击热区。
- 点击热区时仍调用既有的车站选择流程；相邻站不引入自动猜测或替换逻辑，避免误选。
- 视觉站点大小、路线颜色和站名布局规则保持不变。

### 手势与性能

- 单指拖动和双指缩放继续使用现有 Pointer Events 和统一的 SVG 视口变换。
- 手势进行中只更新 SVG transform，不重算站名布局。
- 手势结束后，或连续变换停顿一小段时间后，再重排站名一次。
- 缩小全图时，拖动速度继续使用屏幕像素位移，不因缩放比例而降低。

## 实现边界

- 主要修改 `index.html` 中的地图手势、面板状态和车站 SVG 结构，以及 `styles.css` 的移动端样式。
- 不修改 `custom-route.js` 的图计算和路线确认契约。
- 不新增依赖，也不改变桌面端地图行为。

## 验收标准

1. 390px 宽度下进入自定义模式时，地图可见高度明显高于当前默认状态，摘要条中的撤销和确认均可使用。
2. 用户可通过点击或上滑展开面板，并可下滑收起。
3. 移动端点击密集站点附近时，透明热区可可靠触发目标站的既有选站操作。
4. 处于最低缩放级别时，连续拖动不会因为站名重排而明显卡顿；松手后站名仍按既有无重叠规则更新。
5. 现有自定义路线测试和全量回归测试通过。
