# 重点车站周边信息设计

## 1. 背景

当前车站百科已经覆盖部分重点车站，但“设施与周边”主要以一段长文本呈现，存在以下问题：

- 周边地点、车站出口、距离和步行时间没有结构化区分；
- 部分车站使用通用模板，无法体现真实的城市和站点差异；
- 内容缺少来源、核对日期和可信度标记；
- 静态网页不适合直接承载实时营业状态、商铺列表等高频变化信息。

本次改造的目标是建立一套可核验、可更新、适合静态网页发布的重点车站周边信息系统。

## 2. 范围

当前线网包含 13 个城市，按照已确认的方案 B 执行：

- 北京、上海、广佛、深圳：每个城市约 50 个重点车站；
- 武汉、成都、重庆、杭州、南京、西安、郑州、天津、苏州：每个城市约 20 个重点车站；
- 总覆盖目标约 380 个重点车站。

重点车站的选择综合考虑：

1. 换乘线路数量和网络中心性；
2. 城市级交通枢纽属性；
3. 景点、商业中心、学校、医院、体育场馆和会展中心等城市功能；
4. 国铁、机场、客运站等跨交通方式连接；
5. 现有百科数据和用户实际使用价值。

## 3. 数据来源与权威性规则

### 3.1 来源优先级

数据按照以下优先级采集和核验：

1. 地铁运营方官网、官方 App、官方公告和官方车站导向资料；
2. 市政府、交通运输局、文旅局及其他政府部门公开资料；
3. 景区、商场、学校、医院、场馆和交通枢纽的官方页面；
4. 地图服务用于发现 POI、核对坐标和估算步行距离；
5. 其他公开资料只作为线索，不作为单独的最终事实来源。

### 3.2 硬性核验规则

- 没有可追溯来源的具体地点不进入正式数据；
- 推荐出口必须由官方车站资料或可核验的官方地图资料支持；
- 步行距离和时间必须标注为“地图估算”，不能写成官方测量值；
- 营业时间、店铺名单、活动信息和临时施工信息不进入静态周边百科；
- 同名地点必须确认城市、站点和实际位置，避免混淆；
- 每条周边信息必须记录来源和最后核对日期；
- 无法确认的字段留空或标记为“待核实”，不能用模板补齐。

### 3.3 地图服务使用边界

地图服务只用于离线数据整理阶段的 POI 发现、坐标辅助和步行距离估算。网页运行时不批量请求地图 API，也不在公开前端代码中放置服务密钥。

正式发布的数据只保留经过核验的摘要信息、来源链接和核对日期，不直接发布原始 POI 批量响应。

## 4. 数据结构

在现有 `node.wiki` 基础上增加结构化的 `surroundings` 字段，保留现有概述、站台形式和命名历史字段。

```json
{
  "surroundings": {
    "version": "2026-08",
    "reviewedAt": "2026-08-11",
    "verification": "verified",
    "tags": ["旅游地标", "城市枢纽"],
    "summary": "车站位于城市核心片区，周边连接城市地标和公共空间。",
    "places": [
      {
        "name": "周边地点名称",
        "type": "旅游地标",
        "description": "经过核验的简短介绍。",
        "recommendedExits": ["B口"],
        "walkingDistanceM": 650,
        "walkingMinutes": 9,
        "distanceType": "map_estimate",
        "sourceIds": ["source-1"],
        "reviewedAt": "2026-08-11",
        "verification": "verified"
      }
    ],
    "connections": [
      {
        "name": "接驳对象名称",
        "type": "国铁枢纽",
        "description": "确认过的换乘或接驳关系。",
        "sourceIds": ["source-2"],
        "reviewedAt": "2026-08-11",
        "verification": "verified"
      }
    ],
    "sources": [
      {
        "id": "source-1",
        "publisher": "资料发布方",
        "title": "资料标题",
        "url": "https://www.bjsubway.com/station/xltcx/?id=1",
        "accessedAt": "2026-08-11",
        "type": "official"
      }
    ]
  }
}
```

允许的 `verification` 状态：

- `verified`：已由权威来源核验；
- `needs_review`：已有线索但尚未达到发布标准。

距离字段单独使用 `distanceType` 标记：

- `official`：来源提供的官方距离或步行信息；
- `map_estimate`：通过地图服务估算的距离或时间；
- `not_available`：暂时没有可靠距离数据。

## 5. 页面设计

点击车站后，现有百科抽屉调整为以下信息顺序：

1. 车站概览；
2. 途经线路；
3. 周边亮点；
4. 出口与接驳；
5. 无障碍与服务设施；
6. 信息来源与最后核对日期。

### 5.1 周边亮点卡片

每个地点独立展示：

- 类型图标和类型名称；
- 地点名称；
- 一句话说明；
- 推荐出口；
- 步行距离和预计步行时间；
- “地图估算”标记；
- 来源和核对日期。

### 5.2 空状态和不完整状态

- 没有周边数据：显示“该站周边资料正在整理”；
- 只有部分资料：正常展示已有内容，并显示核对状态；
- 资料过期或待确认：降低视觉强调，不伪装为已核实信息；
- 不再使用通用模板生成具体商圈、景点或设施名称。

### 5.3 移动端体验

- 周边地点使用纵向卡片，不采用横向滚动；
- 来源信息收纳在卡片底部，避免正文过长；
- 点击地点可跳转到地图服务查看实时路线；
- 不让周边信息遮挡路线规划和车站选择操作。

## 6. 数据生产流程

```text
确定重点车站名单
    ↓
整理官方车站资料
    ↓
整理政府和地点官方资料
    ↓
使用地图服务辅助查找 POI 和估算距离
    ↓
人工逐站核对地点、出口和归属关系
    ↓
写入结构化 surroundings 数据
    ↓
运行完整性和重复模板检查
    ↓
在百科抽屉中展示
```

第一阶段先完成四个核心城市的 200 个车站；第二阶段完成其余九个城市的 180 个车站。每一阶段都需要独立检查后再进入下一阶段。

## 7. 测试与验收

### 数据验收

- 380 个目标车站有明确覆盖清单；
- 每个正式地点至少有一个可访问来源；
- 推荐出口与地点关系可以追溯；
- 所有距离字段都有单位；
- 地图估算值有明确标记；
- 不再出现大规模完全相同的周边模板；
- 没有把实时营业信息写入静态数据；
- 来源日期和数据版本完整。

### 页面验收

- 有周边数据的车站显示结构化卡片；
- 没有数据的车站显示清晰空状态；
- 桌面端抽屉可以正常滚动；
- 移动端卡片不横向溢出；
- 来源链接可以点击；
- 长地点名称不会与其他字段重叠；
- 打开百科不会影响路线规划和地图操作。

### 更新验收

- 重新编译线网数据时保留 `surroundings`；
- 单个城市可以独立更新；
- 单个车站可以独立修订；
- 数据版本和核对日期会随更新同步变更。

## 8. 暂不纳入

- 实时营业时间；
- 实时客流；
- 商铺和餐饮实时推荐；
- 自动抓取所有车站的完整 POI；
- 将地图 API Key 放进 GitHub Pages 前端；
- 没有来源的自动生成周边文案。

## 9. 预期结果

完成后，车站百科将从“车站介绍卡片”升级为“可核验的车站周边指南”：用户可以知道车站附近有什么、应该从哪个出口出站、步行大约多远，同时能够看到信息来源和核对时间。
