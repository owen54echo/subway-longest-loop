# 项目架构说明

## 运行时分层

- `index.html`：页面控制器，负责交互状态、地图渲染、路书和分析模块编排。
- `city-registry.js`：从已编译数据生成城市入口，避免新增城市时同步维护 HTML 按钮。
- `calculation-topology.js`：将地图展示拓扑转换为路线计算拓扑，处理停用站和跨站直通规则。
- `topology-rules.js`：集中维护已核对的合并站、直通站和合并线路规则。
- `route-rules.js`：集中维护区间距离、逻辑线路和换乘计算。
- `solver-contract.js`：校验求解器请求、结果、权重和预计算拓扑指纹。
- `solver-worker.js`：Web Worker 中的最长路径/闭环搜索；所有输入由页面或预计算脚本先构造，再由契约校验。
- `custom-route.js`：自定义路线的最少站跳转和路书结果生成。

## 数据更新流程

1. 修改 `data/cities.json` 添加或调整城市目录；正式运营线路通过 `operational_lines` 白名单控制。
2. 运行 `compile_subways.py` 抓取并编译数据。任何城市或合并城市抓取失败、输出为空、区间悬空时都会中止，不覆盖现有 `subway_data.js`。
3. 编译输出中的 `stationId` 优先由城市和经纬度生成，站名修正不会直接造成身份漂移。
4. 运行 `precompute_city_extremes.js` 生成分片，再用 `merge_city_extremes_results.js` 合并。结果携带拓扑指纹，拓扑变化后旧结果自动失效。
5. 修改车站状态、周边信息或拓扑规则后，重新运行项目验证脚本。

## 算法不变量

- 路线必须从指定起点开始；闭环必须回到起点；固定终点必须到达终点。
- 每条区间最多使用一次。
- 不允许重复车站时，闭环只允许起点在首尾出现两次。
- 不允许重复线路时，线路按 `logicalLine` 计算，官方合并线和支线使用同一逻辑线路。
- 换乘次数必须排除已声明的直通换乘。
- 超时结果只能标记为 `current_best`，不能标记为 `exact`。
- 任意预计算结果必须通过当前拓扑指纹和路径连通性校验后才能进入缓存。

## 新增城市检查清单

- 在 `data/cities.json` 添加城市编码、名称、拼音和正式运营线路白名单。
- 检查所有节点地图坐标、经纬度、线路颜色和区间距离。
- 检查是否存在官方合并线、支线或不下车直通段，并只在 `data/topology-rules.json` 登记已确认规则。
- 重新编译、预计算并运行 `bash scripts/verify_project.sh`。
- 检查城市入口、起终点选择、自定义路线、最长路线、距离模式、路书和分享卡。
